# دليل التقنيات

## الهدف

يستخدم Friend Feud مستودعًا واحدًا لتطبيق الويب وخادم API. هذا المستودع يجهز طبقة التطوير والاتصال فقط؛ لا يحتوي على قواعد أسئلة أو نقاط أو جولات.

## واجهة الويب

- **React 19 وTypeScript 6:** واجهة React واحدة تعرض مسارات مستقلة للأجهزة: `/team-one` و`/team-two` و`/host` و`/display`.
- **Vite 8:** خادم تطوير سريع وبناء إنتاجي. يستمع على `0.0.0.0` لتجربة الأجهزة على شبكة Wi-Fi المحلية.
- **Tailwind CSS 4:** تنسيق عبر إضافة Vite الرسمية. لا يستخدم إعداد Tailwind 3 أو ملف `tailwind.config.js`.
- **shadcn/ui:** نقطة إعداد عبر `components.json` وalias `@/` ومساعد الأصناف. أضف المكونات المطلوبة لاحقًا باستخدام CLI بدل نسخ واجهة نهائية الآن.
- **Socket.IO Client:** جاهز للاتصال بالخادم عند إضافة بروتوكول اللعب.
- **GSAP:** مثبت للاستخدام مستقبلًا عند الحاجة؛ لا توجد حركات لعب في هذه المرحلة.

## الخادم

- **Node.js 24 LTS:** إصدار المضيف الحالي هو `24.13.0`. إعداد المشروع يستهدف Node 22 أو أحدث.
- **NestJS 11 وTypeScript:** تطبيق API واحد منظم كوحدات. اختر NestJS 11 لتوافق CLI ثابت مع إصدار Node الموجود.
- **Socket.IO عبر NestJS WebSockets:** بوابة الاتصال الحالية تختبر حدث `diagnostic:ping`/`diagnostic:pong` فقط.
- **مرجع الحالة مستقبلًا:** يجب أن يقرر الخادم ترتيب الأحداث وحالة المباراة؛ لا تُستخدم ساعة المتصفح أو نتيجة محلية من الواجهة كمرجع.

## التخزين

- **SQLite عبر TypeORM وbetter-sqlite3:** ملف محلي واحد في `data/friend-feud.sqlite`، يفتحه الخادم فقط.
- **Migrations:** إعداد TypeORM يستخدم migrations ويترك `synchronize: false`. لا توجد جداول لعب أو migrations فعلية بعد.
- **لا خدمات إضافية:** لا يتطلب المشروع MySQL أو Redis أو Docker أو خدمة سحابية.

## التشغيل دون إنترنت

يتطلب تنزيل الحزم أول مرة اتصالًا بالإنترنت. بعد نجاح `npm install`، يعمل التطوير والاتصال المحلي دون إنترنت، ما دامت الأجهزة على الشبكة المحلية نفسها. لا تعتمد الواجهة الحالية على خطوط أو صور أو APIs خارجية.
