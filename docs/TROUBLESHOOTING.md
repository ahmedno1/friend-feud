# استكشاف الأعطال

## فشل `npm install`

- تحقق من `node --version` و`npm --version` ومن اتصال npm registry أثناء التثبيت الأول.
- استخدم Node.js 22 أو أحدث. المشروع اختُبر على Node `24.13.0` مع NestJS CLI 11.
- عند تعارض peer dependencies، لا تستخدم `--force` أو `--legacy-peer-deps`؛ راجع نسخ `apps/api/package.json` أولًا.
- إذا أوقفت التثبيت يدويًا، أعد تشغيل `npm install` من جذر `friend-feud` لا من مجلد تطبيق منفرد.

## المنفذ مستخدم

- Vite يستخدم `5173` وNest يستخدم `3000` افتراضيًا.
- أوقف العملية التي تستخدم المنفذ أو عيّن `API_PORT`؛ يمكن لـ Vite اختيار منفذ تالٍ تلقائيًا.

## الهاتف لا يفتح الصفحة

- تأكد أن الجهازين على شبكة Wi-Fi نفسها وأن عنوان اللابتوب هو عنوان IPv4 الصحيح.
- استخدم عنوان اللابتوب بدل `localhost` على الهاتف.
- تحقق من سماح جدار الحماية باتصالات Node.js على الشبكة الخاصة. لا تعطّل الجدار الناري.

## فشل اتصال API أو Socket.IO

- افتح `http://localhost:3000/health` على اللابتوب وتأكد من استجابة JSON بحالة `ok`.
- تأكد أن `API_HOST=0.0.0.0`، وأن `WEB_ORIGIN` يحتوي أصل الواجهة المستخدمة.
- في شبكة محلية، حدّث `WEB_ORIGIN` بعنوان اللابتوب والمنفذ الفعلي، مثل `http://192.168.1.20:5173`.
- حدث `diagnostic:ping` مخصص لفحص النقل فقط، ولا يمثل أحداث المباراة.

## مشكلة SQLite أو better-sqlite3

- ملف القاعدة محلي تحت `data/`. أغلق عمليات الخادم قبل نقل الملف أو فحصه.
- SQLite CLI غير مطلوب؛ يستخدم Node مشغل `better-sqlite3`.
- تأكد أن مجلد `data` قابل للكتابة، وأن `DATABASE_PATH` نسبي إلى جذر المشروع.
- لا تفعّل `synchronize: true` لمعالجة فشل migration؛ أنشئ migration صريحة عند تعريف مخطط البيانات.

## الاختبارات

- بناء كل التطبيقات: `npm run build`.
- اختبارات Nest الوحدوية: `npm test`.
- اختبارات HTTP وSocket.IO: `npm run test:e2e --workspace @friend-feud/api`.
- عند فشل اختبار Socket.IO على جهاز بطيء، راجع سجل Jest وتأكد من خلو المنفذ الديناميكي؛ الاختبار يطلب منفذًا مؤقتًا.
