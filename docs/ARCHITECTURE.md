# البنية المعمارية

## Monorepo

```text
friend-feud/
  apps/
    web/                 React + Vite + TypeScript
    api/                 NestJS + TypeScript
  data/                  ملف SQLite محلي، غير متعقب في Git
  docs/                  أدلة المشروع
  scripts/               فحوص بيئة التطوير
```

npm workspaces يدير التطبيقات من جذر المستودع، ويولّد ملف قفل واحدًا. واجهة React واحدة تستخدم React Router للمسارات `/team-one` و`/team-two` و`/host` و`/display`.

## تدفق الاتصال

```text
متصفح الجهاز
  ├── HTTP / Socket.IO ──> NestJS على اللابتوب
  │                          └── TypeORM ──> ملف SQLite محلي
  └── تحميل التطبيق ──────> Vite أثناء التطوير
```

يتصل كل جهاز بواجهة الويب على عنوان اللابتوب المحلي. يبقى ملف قاعدة البيانات على المضيف ولا يفتح للأجهزة. تستخدم البوابة الحالية ping/pong تشخيصيًا فقط؛ لا يوجد بروتوكول مباراة.

## المسؤوليات

- `apps/web`: واجهة موحدة ومسارات الأجهزة؛ لا تحتوي منطقًا مرجعيًا للمباراة.
- `apps/api`: نقطة `GET /health` وبوابة Socket.IO لاختبار الاتصال.
- `apps/api/src/database`: خيارات TypeORM ومصدر بيانات CLI ومجلد migrations. المزامنة التلقائية معطلة.
- `data`: موضع قاعدة البيانات؛ تجاهل Git ملفات SQLite المحلية.

عند إضافة سلوك اللعبة مستقبلًا، يحتفظ الخادم بالحالة ويتحقق من الأدوار ويصدر تحديثات Socket.IO. لا تنشئ جداول قبل تعريف مخطط البيانات ومهاجراته.
